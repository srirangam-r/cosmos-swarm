# Material-swap pilot: pre-observation coding

This protocol was written before fetching or viewing any of the 27 clips. Code each clip at native 24 fps, stepping frames around each event. Keep the arm and seed labels, including every failed or ambiguous clip; this is not blinded assessment.

For each clip record: job ID, endpoint, video and sidecar SHA-256, requested and visible object/surface, frame dimensions, frame count and playback fps. Describe initial condition, camera movement, support motion, and whether the object can be identified continuously. Mark any morphing, duplication, occlusion, cuts or scene changes with frame numbers. Mark visible first contact, subsequent contacts and apex frames with a plausible inclusive frame range; mark uncertain events rather than forcing an interpretation. Record whether a rebound is visible after first contact, whether the object is visibly stationary through the end, and the first frame of sustained rest if defensible. A clip ending during motion is right-censored, not a rest time.

Only calculate a flight-time ratio when two consecutive complete flights have identifiable contact boundaries for the same object. Express event-time sensitivity using the recorded boundary ranges, alongside the point estimate; do not call this a complete statistical confidence interval. For peak-height ratios, measure relative to a stable visible contact plane and only with a stable camera, consistent object identity and sufficient spatial resolution; otherwise report not measurable. The first rebound relative to initial drop height is separate from the ratio between successive rebound peaks. A visible dead stop is a qualitative outcome, not an invented zero-valued interval ratio. Do not silently drop clips with no rebound or ambiguous identity from arm summaries: give the denominator and reasons for every exclusion.

Use bclock/bounce_decay only where their planted-case domain and tracking assumptions apply. These were validated on GAUGE-style planted clips, not on arbitrary generated surfaces or deformable beanbags; mark such numerical results unvalidated unless separately validated. Visually check all inferred events against native frames. A 8- or 16-frame pattern is descriptive only when several consecutive cycles are identifiable; do not count a single interval as a locked rhythm.

Report each clip first, then counts and eligible estimates by arm, with n and missingness. At most three seeds per arm do not support reliable arm-level uncertainty or a material ranking; surface, scene, camera and geometry vary together in T2V, so differences do not isolate material causally. A real-photo, matched-scene intervention and appropriate planted validation are needed for a material-specific conclusion. Do not pool object and surface arms into a single rank correlation or treat material categories as having a universal restitution order.
