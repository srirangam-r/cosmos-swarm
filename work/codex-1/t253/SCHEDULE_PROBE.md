# Prototype main-pass schedule trace

`schedule_probe.py` is an undeployed diagnostic for task 253's provenance gate. Inside the server lock, after auxiliary/dry passes have finished and after the final main-pass scheduler is assigned, wrap `pipe(**call)` as `with trace_schedule(pipe.scheduler) as schedule_trace:`. Copy the resulting `schedule_trace` into the job sidecar while still under that lock, along with the server revision and scheduler config. If the scheduler object is replaced during the main pass or the trace contains no step calls, the trace is invalid. Keep the traced scheduler identity and check that `pipe.scheduler is traced_scheduler` afterward. Do not rely on requested step count or post-lock scheduler reads. Compare call timesteps to captured schedule, count, and sigmas; handle custom start-at-step schedulers explicitly.

This records the scheduler's arrays at the first actual `step` and each step's timestep argument. It does not record sigma arguments used inside `step`, prove generator device, or establish that a sampler is correct. Per-step GPU-to-CPU conversions may impose synchronization overhead. Compatibility and effects on the real Diffusers/Cosmos pipeline and all hooks are **untested**; three fake-scheduler unit tests only verify basic output preservation, copying and cleanup, including exception paths. Before production, test on a real pipeline, compare decoded output with instrumentation off/on, and validate the sidecar against known scheduler configurations. Do not treat the prototype itself as evidence that any existing job used a schedule.

Run `python3 -m unittest discover -s work/codex-1/t253 -p test_schedule_probe.py -v` from the repo root.
