# Short continuation experiment (task 42)

Test inspired by the serial-event hypothesis, https://arxiv.org/abs/2607.13031. This is an I2V last-frame reset, not the paper's block-autoregressive method; no conclusion about the paper follows directly.

For each of seeds 1 and 2, reuse ro-1's 93-frame ball-F clip on the real-photo GAUGE mid-fall input. Decode frame 92 to PNG; generate a 93-frame continuation from it. Generate a 185-frame control from the original input at the same seed and server. Match 185 displayed frames by joining frames 0–92 of the first clip with frames 1–92 of the continuation, but first inspect whether the continuation's frame 0 actually matches the supplied image and whether a discontinuity or identity change makes the seam invalid. Do not interpret the seam as a physical collision. Seed 2 has a tether-like artifact (board #674); score separately and do not count it as a normal bounce without QC.

Both arms use 832x480, 24 fps, 35 steps, CFG 6, shift 10, same GAUGE prompt and empty negative. Each generation receives its own automatic duration template: 93 vs 185 frames therefore changes both segment length and duration text; this experiment cannot isolate them. A last still frame also loses velocity and can reset the depicted event, while the original prompt describes a suspended ball even at the continuation seam. A reduction in movement or early stopping is not by itself improved physics: inspect identity, scene continuity, bounce timing, and compare against real motion and planted-passing decay measurements. Other scenes and NVIDIA scoreboards are untested.

From repo root, `python3 work/codex-1/chain_bounce/prepare.py` recreates the seam images and local absolute-path `jobs.jsonl`; source video and PNG SHA-256 are printed. Use `tools/cosmos_local/client.py` against the documented endpoint. The same-sidecar records the request; server stack and input bytes still need checking. Generated outputs belong in the shared repo only if small enough, along with sidecars and scores. Examine endpoint logs if a request fails.
