# Independent review of finding 420

The following is a source inspection, not an independent replication of the DROID LPIPS values. We did not access the author's videos or scoring artifacts. Check with `python3 check.py` (numpy, OpenCV; our run used OpenCV 4.13.0).

At diffusers commit `86ef420`, `Cosmos3OmniPipeline` sets `VideoProcessor(vae_scale_factor=self.vae_scale_factor_spatial, resample="bilinear")` ([pipeline lines 455–459](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/pipelines/cosmos/pipeline_cosmos3_omni.py#L455-L459)). For the 16x spatial scale in finding 420, action preprocessing calls `preprocess_video` without explicit spatial dimensions ([lines 704–712](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/pipelines/cosmos/pipeline_cosmos3_omni.py#L704-L712)); the image processor rounds each dimension down to a multiple of that scale ([image processor lines 561–605](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/image_processor.py#L561-L605)) and resizes to those dimensions ([lines 684–695](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/image_processor.py#L684-L695)). Thus a 640×540 PIL conditioning image becomes 640×528; no pixel crop is involved. The action pipeline then selects a target canvas and pads its content ([lines 713–752](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/pipelines/cosmos/pipeline_cosmos3_omni.py#L713-L752)). The 480-tier landscape bin in question is 736×544 ([lines 195–200](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/pipelines/cosmos/pipeline_cosmos3_omni.py#L195-L200)).

By contrast, pinned cosmos-framework invokes `reflection_pad_to_target` on the original video ([action.py lines 121–138](https://github.com/NVIDIA/cosmos-framework/blob/55f0554/cosmos_framework/inference/action.py#L121-L138)). That function does not upscale; it records the original content height and pads bottom and right ([transforms.py lines 194–233](https://github.com/NVIDIA/cosmos-framework/blob/55f0554/cosmos_framework/data/generator/action/utils/transforms.py#L194-L233)). Given a 736×544 target, its content height is 540.

**Workaround caution:** pre-reflect-padding a 540-high image to 544 avoids the initial resize, but the pinned diffusers code will record content height 544, not 540, and its latent crop uses `content_h // 16` ([pipeline lines 751–761](https://github.com/huggingface/diffusers/blob/86ef420/src/diffusers/pipelines/cosmos/pipeline_cosmos3_omni.py#L751-L761)). It is therefore not established to match the reference path: the content mask/crop and output geometry may differ. Do not compare its outputs without checking the conditioning and output geometry end to end. This is source-based inference, not an executed model test.

As a sanity demonstration only, OpenCV linear 540→528 and area 528→540 on three deterministic synthetic 640×540 grayscale patterns yields mean absolute error 0.1074, 86.0000 and 10.7333/255 levels for gradient, one-pixel stripes and 8-pixel checkerboard respectively (PSNR 57.82, 8.60 and 20.65 dB). These controlled patterns illustrate content dependence; they are neither LPIPS nor real DROID scores, and OpenCV interpolation is not asserted to be bit-identical to the PIL path.
