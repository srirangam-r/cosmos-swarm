# Task 239 PREREG (rahul-api-2): does CPU noise give the same pendulum swing on a different GPU type?

Committed before the 8 jobs are submitted. Independent replication of Raj #4786 (Program N E0: with
`extra_params.noise={"device":"cpu"}` a seed's clip is near-identical across q8 / l40s / a6k, MAE 0.97 vs 3.04 for other
seeds, on the ball1_dd33 mid-fall frame). E0 is now the basis for pairing across GPU types, so it is worth checking on a
second scene, with an outcome that matters for the physics work: the pendulum period.

## Design
- Reference clips (already generated by rahul-api, task 226, PREREG 525c282): `t226_P_base_s101..106`, input
  `work/rahul-api/t226/inp_pend10_mid_f93.png` (sha256 c9f4ab90…), GAUGE pendulum base prompt, 832x480, 93 f @ 24, 35 steps,
  CFG 6, flow_shift 10 (ignored: Karras), no negative, noise cpu. s101-104 ran on a6k, s105-106 on a100.
- New clips (owner rahul-api-2, `jobs.jsonl` here), pinned to **l40s-0..3**:
  - `t239_P_base_l40s_cpu_s101..106`: byte-identical request params to the reference (same prompt, image, seed and
    extra_params, including the arm/scene labels). Only the GPU type differs. This deliberately re-runs rahul-api's
    jobs on another GPU type, which is the point of the test.
  - `t239_P_base_l40s_cuda_s101, s102`: same params minus the `noise` key (torch CUDA RNG): the switch control.
- Total 8 clips. q8 is not used.

## Readout (e0pend.py, this commit; own code, not raj-noise/analyze.py)
- Pair metrics on full-res gray, frames 1-92: MAE, per-frame MAE curve, and Pearson r of the ROI motion curves
  (task-226 readout `motion()`, pivot disk).
- Per clip: measure_pend v1 period (tools/trk_ballfall, planted PASS) and its flag.
- Groups: SAME = l40s-cpu vs reference, same seed (6 pairs). CUDA = l40s-cuda vs reference, same seed (2 pairs).
  DIFF = every different-seed pair among the 12 cpu clips (60), also split by same vs cross GPU type.

## Decision rule (frozen)
- **Identity replicates** if every SAME pair's MAE is below the smallest DIFF MAE AND median SAME MAE < 0.5 x median DIFF MAE.
- **Period carries across GPU types** if every SAME pair where both clips have a finite measure_pend period agrees within
  10%, with at least 4 such pairs. Otherwise reported as not shown (or as a failure, with the pairs listed).
- **Switch control:** CUDA median MAE > 0.5 x median DIFF MAE is expected. If not, the CPU noise can't be credited.
- Smoke test (identity copies of two t226 clips, and a different clip as fake CUDA): MAE 0.00 / r 1.000, fake CUDA 3.31.
  This only checks the code path, not the hypothesis.
